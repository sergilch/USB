# AFE ↔ Digital Interface Specification — Draft 0.1

*Phase A0 of `AFE_INTEGRATION_PLAN.md`. Created 2026-11-10. Status: **draft for review with the analog team**; nothing in here is frozen until every item marked **TBC** has an answer and both sides sign off (milestone AM1).*

Status labels used below:

| Label | Meaning |
|---|---|
| **Fixed** | Set by the existing digital RTL or by the USB 2.0 / ULPI 1.1 specification. Changing it means changing the RTL. |
| **Proposed** | The digital side's proposal; the analog team accepts or counter-proposes. |
| **TBC** | Needs data or a decision from the analog team (question number in section 8). |
| **New** | Pin or block that does not exist in the analog design yet. |

## 1. Supply and voltage domains

| Domain | Voltage | Blocks | Status |
|---|---|---|---|
| VDD33 (analog) | 3.3 V | HS RX, HS TX; planned: FS/LS drivers and receivers, terminations, squelch / disconnect, VBUS / ID comparators | Fixed (block description) |
| VDD18A (analog) | 1.8 V | CDR + PLL | Fixed (block description) |
| VDD18 (digital) | 1.8 V | Digital core on xh018 D_CELLS_JIHD, BBSUD8F ULPI pads | Fixed |
| Source of the 1.8 V supplies | — | Internal LDO from VDD33 (as in the USB3320) or external | TBC (Q13) |

Crossing rules (Proposed):

- Every **slow** signal between VDD33 and VDD18 goes through a level shifter with an isolation clamp controlled by `iso_en` (digital, power sequencer). The clamp value is the "isolated" value in section 3.
- The two **480 Mbit/s** signals that cross VDD33 ↔ 1.8 V (`TX_IN_P/N` into the TX, `RX_OUT_P` into `CDR_DATA`) must not use library level shifters. Proposal: the HS TX gets a 1.8 V input pre-driver, and the HS RX gets a 1.8 V output stage (or the shift sits inside the CDR input). Q8.
- No signal from a powered domain may back-power an unpowered one (check during A7).

## 4. Timing

### 4.1 HS transmit

| Parameter | Value | Status |
|---|---|---|
| `TX_IN_P/N` change | On the rising `clk_bit` edge + clock-to-Q (0.3–1.2 ns over corners, section 7.2) | Fixed |
| P/N skew at the TX input pins | ≤ 50 ps (Proposed; to be checked against the TX's tolerance) | TBC |
| `TX_EN` lead before the first SYNC bit | `TX_LEAD` bit times, programmable 0–31, default from the TX enable time (Q4) | Proposed |
| `TX_EN` lag after the last EOP bit | `TX_LAG` bit times, programmable 0–7 | Proposed |
| Output delay `TX_IN` → `TX_OUT` | constant, any value, its variation over corners needed for the USB TX start-delay budget | TBC (Q4) |

The digital implements the lead by delaying the data path by `TX_LEAD` bits in a shift register on `clk_bit`. This adds `TX_LEAD` bit times to the PHY's TX start delay, which must be checked against the ULPI 1.1 / USB 2.0 budget once the defaults are known.

### 4.2 HS receive: SYNC budget and lock

The digital receive chain has been measured (`tb_usb_rx_datapath` with a fixed number of lost leading SYNC bits, 2026-11-10; loss counted from the first SYNC bit at the `usb_rx_hs_frontend` inputs, so the front end's own synchronizer is included):

| `HS_ZMIN` (SYNC zeros required) | SYNC bits the digital needs | Max. lost bits of a 32-bit SYNC | **Budget for squelch release + CDR lock + `LOCK_DLY` with a 12-bit SYNC** (5 hubs) |
|---|---|---|---|
| 6 (current default) | 8 | 24 | **4 bit times = 8.3 ns** |
| 4 | 6 | 26 | 6 bit times = 12.5 ns |
| 3 | ≤ 4 (limit not searched) | ≥ 28 | ≥ 8 bit times = 16.7 ns |

A lower `HS_ZMIN` makes it more likely that bad bits before lock are taken for a SYNC end. That risk is small as long as `hs_cdr_lock` only rises after the CDR delivers correct bits, but it must be checked with the CDR model (A3).

Requirements (TBC with Q1 / Q2):

| Parameter | Requirement |
|---|---|
| Squelch release (line active → `SQUELCH_A` = 0) + CDR delivering correct bits | ≤ the budget above, minus `LOCK_DLY`. With today's `HS_ZMIN` = 6 that is **4 bit times in total**, which is very tight for a bang-bang CDR; the realistic target is `HS_ZMIN` = 4 (6 bit times) if the false-SYNC check in A3 passes. |
| `hs_rxd` setup / hold to rising `clk_rx` at the digital capture flop | ≥ 0.4 ns / ≥ 0.1 ns (Proposed, from the slow-corner flop data in section 7.2) |
| Squelch assertion after the line goes idle | < 8 bit times after the EOP (the digital ends the packet on squelch; a slower squelch is fine, but it delays rearming SYNC detection) |
| CDR frequency tracking | ±1000 ppm (host ±500, own ±500). The digital elastic buffer covers this for 1027-byte packets (`tb_usb_rx_datapath`). |

`hs_cdr_lock` (Proposed): the digital asserts it `LOCK_DLY` bit times after `hs_squelch` falls (register, 0–7, default 0 if the CDR delivers clean bits from squelch release, else the measured lock time), and drops it with squelch.

### 4.3 PLL lock

| Parameter | Value | Status |
|---|---|---|
| PLL lock time from `PLL_EN` | ≤ 100 µs (Proposed; the ULPI PHY holds DIR high until the clock is valid) | TBC |
| Digital lock criterion | count `clk_bit` cycles over 256 `ref_dig` cycles: expected 5120, accepted ±5 (±0.1 %), 4 consecutive good windows → `pll_lock` = 1, one bad window → `pll_lock` = 0 and the loss-of-lock flag | Proposed |

### 4.4 FS / LS

The digital DPLL samples `rxrcv`, `rxdp`, `rxdm` asynchronously on `clk_bit` (2-FF synchronizers), so no setup / hold is required. The receivers must keep the D+ / D− skew below 5 ns (tested in `tb_usb_rx_datapath`) and must not produce SE1 glitches longer than 1 FS bit.

## 5. Power-up and suspend sequence (Proposed)

```
POR released, pwr_good = 1
  → bias_en = 1, wait T_BIAS (TBC)
  → pll_en = 1, wait pll_lock (digital detector), DIR held high on ULPI
  → release digital reset, iso_en = 0
  → rx_en / cdr_en / tx enables as the mode requires (FS/LS receivers on by default)
Suspend (ULPI SuspendM = 0):
  → hs_tx_en = 0, rx_en_hs = 0, cdr_en = 0, pll_en = 0 (when ClockSuspendM = 0)
  → FS/LS receivers, squelch-independent resume detection and VBUS comparators stay on
Resume: reverse order, PLL lock before CLKOUT restarts.
```

## 7. Digital-side facts measured in A0

### 7.1 SYNC tolerance

See section 4.2. Method: a scratch copy of `tb_usb_rx_datapath` with squelch release and CDR lock at a fixed bit position, all HS / FS / LS cases of the testbench, `HS_ZMIN` 6 / 4 / 3.

### 7.2 480 MHz timing on xh018

No Liberty-based STA is installed (OpenSTA missing; Yosys 0.33 has no Liberty timing). Estimate: ABC mapping onto D_CELLS_JIHD with buffering and gate sizing (`map -D 2083; buffer; upsize; dnsize; stime`), per module, worst register-to-register logic path, no wire load and no clock skew, plus the flip-flop overhead from the Liberty tables.

Flip-flop overhead (DFRQJIHDX1, light load): clock-to-Q 0.23–0.39 ns fast, 0.32–0.56 ns typ, 0.62–1.07 ns slow; setup ≈ 0.15–0.2 ns typ, 0.3–0.4 ns slow. **At the slow corner (1.62 V, 125 °C) only ≈ 0.6 ns of the 2.08 ns period is left for logic; at typical ≈ 1.3 ns.**

| Module | Clocked every bit (480 MHz)? | Worst logic path, slow | typ | Verdict |
|---|---|---|---|---|
| `usb_rx_nrzi_decoder` | yes (`clk_rx`) | 0.92 ns | 0.45 ns | fails slow, passes typ |
| `usb_rx_sync_detect` | yes | 1.62 ns | 1.00 ns | fails slow, typ marginal |
| `usb_rx_bit_unstuffer` | yes | 1.21 ns | 0.50 ns | fails slow |
| `usb_rx_deserializer` | yes | 1.43 ns | 1.01 ns | fails slow, typ marginal |
| `usb_rx_eop_check` | yes | 1.69 ns | 1.20 ns | fails slow, typ ≈ no margin |
| `usb_rx_elastic_buffer` (write side) | yes (`clk_rx`) | 2.98 ns | 1.58 ns | fails both |
| `usb_rx_hs_frontend` | yes | 0.30 ns | 0.14 ns | passes |
| `usb_tx_serializer` | shift / bit counter yes, inputs are 8-cycle multicycle paths | 3.00 ns (path type not separated) | 1.46 ns | needs real STA with multicycle constraints |
| `usb_bit_stuffer`, `usb_nrzi_encoder` | no: byte-wide on `ce60`, 8-cycle multicycle (16.7 ns) | 4.39 / 3.00 ns | 2.25 / 1.40 ns | pass as multicycle paths |

**Conclusion:** the HS receive bit chain does not run at 480 MHz on xh018 at the slow corner, and only marginally at typical. This makes I12 (Q12) a required decision rather than an option. Either:

- **(a)** the CDR delivers its data 1:4 demultiplexed (4 bits on `clk_rx` ÷ 4 = 120 MHz, plus the divided clock), and the digital RX chain is reworked to process 4 bits per cycle (recommended: also cuts power); or
- **(b)** the digital RX chain is restructured into a deeper pipeline at 480 MHz, with at most one or two gates between flops. That is still at the limit at the slow corner, and the elastic-buffer write side would need a redesign.

On the TX side the last bit-rate stage is the serializer shift register. It probably fits (flop → mux → flop), but a real STA must confirm it, or the analog TX takes 2 or 4 bits in parallel and does the last serialization itself.

Next step: install OpenSTA (or use the analog team's / foundry STA flow) and repeat this with SDC multicycle constraints (WORK_PLAN 9.1).
