# AFE ↔ Digital Interface Specification — Draft 0.1

*Phase A0 of `AFE_INTEGRATION_PLAN.md`. Created 2026-11-10. Status: **draft for review with the analog team**; nothing in here is frozen until every item marked **TBC** has an answer and both sides sign off (milestone AM1).*

Status labels used below:

| Label | Meaning |
|---|---|
| **Fixed** | Set by the existing digital RTL or by the USB 2.0 / ULPI 1.1 specification. Changing it means changing the RTL. |
| **Proposed** | The digital side's proposal; the analog team accepts or counter-proposes. |
| **TBC** | Needs data or a decision from the analog team (question number in section 8). |
| **New** | Pin or block that does not exist in the analog design yet. |

Crossing rules (Proposed):

- Every **slow** signal between VDD33 and VDD18 goes through a level shifter with an isolation clamp controlled by `iso_en` (digital, power sequencer). The clamp value is the "isolated" value in section 3.
- The two **480 Mbit/s** signals that cross VDD33 ↔ 1.8 V (`TX_IN_P/N` into the TX, `RX_OUT_P` into `CDR_DATA`) must not use library level shifters. Proposal: the HS TX gets a 1.8 V input pre-driver, and the HS RX gets a 1.8 V output stage (or the shift sits inside the CDR input). Q8.
- No signal from a powered domain may back-power an unpowered one (check during A7).

## 4. Timing

### 4.1 HS transmit

| Parameter | Value | Status |
|---|---|---|
| `TX_IN_P/N` change | On the rising `clk_bit` edge + clock-to-Q (0.3–1.2 ns over corners, section 7.2); `TX_IN_P` and `TX_IN_N` come from two separate flops (`usb_afe_tx_if`) | Fixed |
| P/N skew at the TX input pins | ≤ 50 ps (Proposed; to be checked against the TX's tolerance) | TBC |
| `TX_EN` lead before the first SYNC bit | `TX_LEAD` bit times, programmable 0–31, default from the TX enable time (Q4). `TX_IN_P/N` show J during the lead. | Proposed |
| `TX_EN` lag after the last EOP bit | `TX_LAG` bit times, programmable 0–7. `TX_IN_P/N` hold the EOP level during the lag, so the line EOP is 8 + `TX_LAG` bits (receivers take any bit-stuff error as EOP). | Proposed |
| Output delay `TX_IN` → `TX_OUT` | constant, any value, its variation over corners needed for the USB TX start-delay budget | TBC (Q4) |

The digital implements the lead by delaying the data path by `TX_LEAD` bits in a shift register on `clk_bit` (`usb_afe_tx_if`, phase A2). Latency from the serializer to the pins: data `TX_LEAD` + 3 bit times, `TX_EN` rise 3, `TX_EN` fall `TX_LEAD` + 3 + `TX_LAG`. This adds `TX_LEAD` + 3 bit times to the PHY's TX start delay, which must be checked against the ULPI 1.1 / USB 2.0 budget once the defaults are known. `TX_LEAD` + `TX_LAG` + 3 must stay below the inter-packet gap (≥ 88 bit times), otherwise `TX_EN` stays on across the gap; the ranges above guarantee that. New values are taken over only while the TX is idle.

**Default from the A2 simulation** (`tb_usb_afe_tx_if`, `afe_hs_tx_bm` with `T_EN` = 20 ns, line sampled 1.0 ns after each `clk_bit` edge): the whole SYNC reaches the line when `TX_LEAD` · 2.083 ns ≥ `T_EN`, i.e. `TX_LEAD` = ⌈`T_EN` / bit time⌉ = 10; then the line shows less than one bit of J before SYNC. Each bit of lead less loses one SYNC bit (lead 0: 10 bits lost, which eats into the receivers' SYNC budget behind hubs, section 4.2); each bit more adds one bit of J before SYNC. So the default is ⌈`T_EN` / 2.083 ns⌉ with `T_EN` the worst-corner value from Q4.

Idle clamp: `drv_dis` (non-driving OpMode) or `iso_en`, registered once in the digital, sets `TX_IN_P` = 1, `TX_IN_N` = 0, `TX_EN` = 0 and the FS/LS controls to their idle values on the second `clk_bit` edge, and drops the rest of a packet in progress (it never resumes in the middle).

### 4.2 HS receive: SYNC budget and lock

The digital receive chain has been measured (`tb_usb_rx_datapath` with a fixed number of lost leading SYNC bits, 2026-11-10; loss counted from the first SYNC bit at the `usb_rx_hs_frontend` inputs, so the front end's own synchronizer is included):

| `HS_ZMIN` (SYNC zeros required) | SYNC bits the digital needs | Max. lost bits of a 32-bit SYNC | **Budget for squelch release + CDR lock + `LOCK_DLY` with a 12-bit SYNC** (5 hubs) |
|---|---|---|---|
| 6 (current default) | 8 | 24 | **4 bit times = 8.3 ns** |
| 4 | 6 | 26 | 6 bit times = 12.5 ns |
| 3 | ≤ 4 (limit not searched) | ≥ 28 | ≥ 8 bit times = 16.7 ns |

A lower `HS_ZMIN` makes it more likely that bad bits before lock are taken for a SYNC end. That risk is small as long as `hs_cdr_lock` only rises after the CDR delivers correct bits, but it must be checked with the CDR model (A3).

Requirements (TBC with Q1 / Q2):

| Parameter | Requirement |
|---|---|
| Squelch release (line active → `SQUELCH_A` = 0) + CDR delivering correct bits | ≤ the budget above, minus `LOCK_DLY`. With today's `HS_ZMIN` = 6 that is **4 bit times in total**, which is very tight for a bang-bang CDR; the realistic target is `HS_ZMIN` = 4 (6 bit times) if the false-SYNC check in A3 passes. |
| `hs_rxd` setup / hold to rising `clk_rx` at the digital capture flop | ≥ 0.4 ns / ≥ 0.1 ns (Proposed, from the slow-corner flop data in section 7.2) |
| Squelch assertion after the line goes idle | < 8 bit times after the EOP (the digital ends the packet on squelch; a slower squelch is fine, but it delays rearming SYNC detection) |
| CDR frequency tracking | ±1000 ppm (host ±500, own ±500). The digital elastic buffer covers this for 1027-byte packets (`tb_usb_rx_datapath`). |

**CDR model results (phase A1, `tb_afe_cdr`, `afe_cdr_bm`: bang-bang loop, random start phase, ±1000 ppm, 300 bursts per cell; L = bits until every sample is correct):**

| Loop step | Data jitter 0 UI | 0.15 UI (70 % eye) | 0.25 UI (50 % eye) |
|---|---|---|---|
| UI/32 (65 ps) | worst 0, mean 0.00 | worst 13, mean 0.40, L > 6 in 2.3 % | worst 51, mean 2.20, L > 6 in 12.3 % |
| UI/16 (130 ps, default) | worst 3, mean 0.01 | worst 9–16, mean 0.3–0.6, L > 4 in 1–5 %, L > 6 in 0.3–3 % | worst 26, mean 1.03, L > 6 in 4.3 % |
| UI/8 (260 ps) | worst 4, mean 0.03 | worst 8, mean 0.21, L > 6 in 0.7 % | does not track (L > 6 in 48 %) |

The mean lock time is well below one bit, but there is a tail: when the packet starts with the sampling phase inside the jittered edge zone, the phase detector's decisions are random and the loop random-walks before it escapes. So with a 70 % eye, about 1–5 % of packets with a 12-bit SYNC miss the 4-bit budget of `HS_ZMIN` = 6. A larger step shortens the tail but stops tracking at 50 % eye. The real CDR needs this statistic from transistor-level simulation (Q2): the worst case alone is not enough.

**Full HS receive chain (`tb_afe_hs_chain`, all models, two `usb_rx_datapath` instances with `HS_ZMIN` 6 and 4, 200 packets per case, 70 % eye):** with a 32-bit SYNC every packet is received by both. With a 16- or 12-bit SYNC, 0.5–1.5 % of the packets are lost or flagged with `HS_ZMIN` = 6 and 0–0.5 % with `HS_ZMIN` = 4. A bad bit before lock can end SYNC detection early; the packet then ends at a false EOP, sometimes without `rx_error`. Such packets were always rejected by the Link's PID check / CRC16, and no wrong packet passed them. So `HS_ZMIN` = 4 does not create undetected errors in this model and lowers the loss; these figures rest on few events, and a longer run is pending.

`hs_cdr_lock` (Proposed, implemented in `usb_afe_rx_if`, phase A3): the digital asserts it `LOCK_DLY` bit times after the synchronized `hs_squelch` falls (register, 0–7) and drops it with squelch. A second register, `SQ_COMP` (0–7), delays the data by that many extra bits against squelch / lock, so line bits that arrived before the squelch detector released are received too.

**A3 results** (`tb_usb_afe_rx_if`, 300 packets per point, 12-bit SYNC unless noted; ideal CDR with the first L line bits replaced by random bits, i.e. a CDR that needs L bits to lock; squelch release 4 ns, hold 12 ns unless swept):

| Setting | Largest L without loss (CDR lock-time margin) | Squelch release that still works | Model chain (`afe_cdr_bm`, 0.15 UI jitter), not received of 300: SYNC 32 / 16 / 12 |
|---|---|---|---|
| `HS_ZMIN` 6, `LOCK_DLY` 0 (current RTL default) | 4 bits | ≤ 12 ns (16 ns: all lost) | 0 / 3 / 2 |
| `HS_ZMIN` 4, `LOCK_DLY` 0 | 4 bits (L = 5–6: ~6 % lost) | ≥ 16 ns | 0 / 1 / 0 |
| **`HS_ZMIN` 4, `LOCK_DLY` 2 (recommended)** | **6 bits** | ≤ 12 ns | 0 / 1 / 0 |
| `HS_ZMIN` 4, `LOCK_DLY` 4 | 6 bits | ≤ 8 ns | 0 / 2 / 0 |
| `HS_ZMIN` 4, `SQ_COMP` 2 | 2 bits | ≥ 16 ns | 1 / 1 / 2 |
| `HS_ZMIN` 6, `SQ_COMP` 2 | 4 bits | ≥ 16 ns | 0 / 3 / 2 |

Findings:

- Squelch release and CDR lock run in parallel, so they are not additive: up to a 12 ns squelch release costs nothing beyond the CDR's own lock bits. The 4-bit "squelch + lock" budget in the table above is therefore a budget for the **CDR alone** (`HS_ZMIN` 6), as long as the squelch releases within 12 ns.
- Wrong bits before lock are the limit: random bits can look like the end of SYNC. `LOCK_DLY` hides them from the SYNC detector. With `HS_ZMIN` 4 and `LOCK_DLY` 2 the CDR may deliver up to **6 wrong bits** after the first line bit of a 12-bit SYNC (12.5 ns), against 4 with the current default. Requirement for Q2: **the CDR delivers correct bits no later than the 7th bit after the first transition, in every corner and for every start phase** (with the recommended setting).
- `SQ_COMP` only helps when the squelch release is slower than about 12 ns (16 ns: `SQ_COMP` 2 recovers it). With a faster squelch it lets idle-line noise in front of SYNC; with `HS_ZMIN` 4 that produced false SYNCs and even lost a packet with a full SYNC. It also costs EOP margin (in the 30-packet sweep `SQ_COMP` 3 failed with a 6 ns squelch hold). Default 0.
- `LOCK_DLY` + the squelch release must not eat too much of the SYNC: `LOCK_DLY` 4 fails with a 12 ns squelch. Rule of thumb for a 12-bit SYNC: squelch release / 2.08 ns + `LOCK_DLY` − `SQ_COMP` ≤ about 7 bits with `HS_ZMIN` 4.
- Squelch hold after the line goes idle: 6 ns is enough for every setting with `SQ_COMP` ≤ 2 (32-bit SYNC, packets up to 64 bytes).
- With the bang-bang CDR model at 0.15 UI jitter, the recommended setting still lost 1 of 600 packets with a shortened SYNC (16 / 12 bits). That is the CDR's lock tail (A1: worst case 9–16 bits), beyond any digital margin; no wrong packet was ever accepted (PID / CRC16 checks). The A3 goal "every packet with a ≥ 12-bit SYNC is received" therefore depends on the real CDR meeting the requirement above.
- Recommendation: change the `HS_ZMIN` used for the PHY to 4 and the `LOCK_DLY` reset value to 2 (decision pending; the RTL default of `usb_rx_datapath` is still 6).

### 4.3 PLL lock

| Parameter | Value | Status |
|---|---|---|
| PLL lock time from `PLL_EN` | ≤ 100 µs (Proposed; the ULPI PHY holds DIR high until the clock is valid) | TBC |
| Digital lock criterion | count `clk_bit` cycles over 256 `ref_dig` cycles: expected 5120 (19.2 MHz: 6400, 26 MHz: 4726), accepted ±5 (±0.1 %), 4 consecutive good windows → `pll_lock` = 1, one bad window → `pll_lock` = 0 and the loss-of-lock flag | Proposed, implemented (A4) |
| Missing reference | no window end for 8191 `clk_bit` cycles counts as a bad window | Proposed, implemented |
| Dead `clk_bit` (VCO stopped, `PLL_EN` = 1) | heartbeat `clk_bit` / 128 checked on `ref_dig`; 32 reference cycles without an edge reset the detector asynchronously | Proposed, implemented |

**A4 results** (`tb_usb_pll_lock_det` with `afe_pll_bm`: first-order frequency settling, τ = 5 µs, VCO 400–500 MHz, start at 400 MHz):

| Case | Result |
|---|---|
| Lock after `PLL_EN` (24 MHz ± 500 ppm; 19.2 MHz) | 70–73 µs (24 MHz), 78 µs (19.2 MHz); the PLL model is inside ±0.08 % after 26.7 µs, the detector adds at most 5 windows (53 µs at 24 MHz, 67 µs at 19.2 MHz) |
| Frequency error +0.05 % | lock kept |
| Frequency error +0.3 % | lock lost after 6.6 µs (≤ 2 windows), `lol` set, CLKOUT stops cleanly; relock, `lol` stays until cleared |
| Reference stops | lock lost after 19.5 µs (≤ 1 window + timeout) |
| `clk_bit` stops with `PLL_EN` = 1 | lock cleared after 1.4 µs; `lol` set once the clock is back |
| `PLL_EN` = 0 (ordered: CLKOUT stopped first) | lock cleared at once, `lol` not set |
| 26 MHz reference with `refsel` = 24 MHz | no lock: the PLL runs into its VCO limit (500 MHz, ratio 19.23) |

Requirement that follows (for Q6 / the PLL design): with the 100 µs budget above, the PLL must be inside ±0.08 % within **45 µs** of `PLL_EN` at 24 MHz (30 µs at 19.2 MHz), worst corner. The detector checks the ratio `clk_bit` / `ref_dig`, i.e. that the PLL follows its reference; a reference that is off but still inside the PLL's range is not detected (the crystal's ±500 ppm are the crystal's job).

**CLKOUT** (`usb_clk_gen`): `ce60` and the 60 MHz `CLKOUT` come from a ÷8 counter on `clk_bit`; `CLKOUT` rises half a `clk_bit` cycle before the edge with `ce60` = 1 and is high / low for 4 cycles each. Its enable (`pll_lock` and not clock suspend) is taken once per period, before the rising edge, so `CLKOUT` only shows complete periods and stops low. `clk_on` = 0 means it has stopped; the power sequencer must wait for `clk_on` = 0 before it turns the PLL off, because stopping `clk_bit` in a high phase would cut the pulse.

### 4.4 FS / LS

The digital DPLL samples `rxrcv`, `rxdp`, `rxdm` asynchronously on `clk_bit` (2-FF synchronizers), so no setup / hold is required. The receivers must keep the D+ / D− skew below 5 ns (tested in `tb_usb_rx_datapath`) and must not produce SE1 glitches longer than 1 FS bit.

## 5. Power-up and suspend sequence (Proposed)

```
POR released, pwr_good = 1
  → bias_en = 1, wait T_BIAS (TBC)
  → pll_en = 1, wait pll_lock (digital detector), DIR held high on ULPI
  → release digital reset, iso_en = 0
  → rx_en / cdr_en / tx enables as the mode requires (FS/LS receivers on by default)
Suspend (ULPI SuspendM = 0):
  → hs_tx_en = 0, rx_en_hs = 0, cdr_en = 0, pll_en = 0 (when ClockSuspendM = 0)
  → FS/LS receivers, squelch-independent resume detection and VBUS comparators stay on
Resume: reverse order, PLL lock before CLKOUT restarts.
```

### 7.1 SYNC tolerance

### 7.2 480 MHz timing on xh018

No Liberty-based STA is installed (OpenSTA missing; Yosys 0.33 has no Liberty timing). Estimate: ABC mapping onto D_CELLS_JIHD with buffering and gate sizing (`map -D 2083; buffer; upsize; dnsize; stime`), per module, worst register-to-register logic path, no wire load and no clock skew, plus the flip-flop overhead from the Liberty tables.

Flip-flop overhead (DFRQJIHDX1, light load): clock-to-Q 0.23–0.39 ns fast, 0.32–0.56 ns typ, 0.62–1.07 ns slow; setup ≈ 0.15–0.2 ns typ, 0.3–0.4 ns slow. **At the slow corner (1.62 V, 125 °C) only ≈ 0.6 ns of the 2.08 ns period is left for logic; at typical ≈ 1.3 ns.**

| Module | Clocked every bit (480 MHz)? | Worst logic path, slow | typ | Verdict |
|---|---|---|---|---|
| `usb_rx_nrzi_decoder` | yes (`clk_rx`) | 0.92 ns | 0.45 ns | fails slow, passes typ |
| `usb_rx_sync_detect` | yes | 1.62 ns | 1.00 ns | fails slow, typ marginal |
| `usb_rx_bit_unstuffer` | yes | 1.21 ns | 0.50 ns | fails slow |
| `usb_rx_deserializer` | yes | 1.43 ns | 1.01 ns | fails slow, typ marginal |
| `usb_rx_eop_check` | yes | 1.69 ns | 1.20 ns | fails slow, typ ≈ no margin |
| `usb_rx_elastic_buffer` (write side) | yes (`clk_rx`) | 2.98 ns | 1.58 ns | fails both |
| `usb_rx_hs_frontend` | yes | 0.30 ns | 0.14 ns | passes |
| `usb_tx_serializer` | shift / bit counter yes, inputs are 8-cycle multicycle paths | 3.00 ns (path type not separated) | 1.46 ns | needs real STA with multicycle constraints |
| `usb_clk_gen` (A4) | yes (`clk_bit`, one falling-edge flop with half-cycle inputs from flops) | 0.60 ns | 0.45 ns | at the slow budget, passes typ |
| `usb_pll_lock_det` (A4, `refsel` static) | yes (`clk_bit` counter, range check one cycle ahead) | 1.63 ns | 0.75 ns | fails slow, passes typ |
| `usb_afe_tx_if` (A2) | yes (`clk_bit`), every path flop → ≤ 2 gates → flop after the A2 restructuring | 1.49 ns | 0.77 ns | fails slow, passes typ |
| `usb_bit_stuffer`, `usb_nrzi_encoder` | no: byte-wide on `ce60`, 8-cycle multicycle (16.7 ns) | 4.39 / 3.00 ns | 2.25 / 1.40 ns | pass as multicycle paths |

**Conclusion:** the HS receive bit chain does not run at 480 MHz on xh018 at the slow corner, and only marginally at typical. This makes I12 (Q12) a required decision rather than an option. Either:

- **(a)** the CDR delivers its data 1:4 demultiplexed (4 bits on `clk_rx` ÷ 4 = 120 MHz, plus the divided clock), and the digital RX chain is reworked to process 4 bits per cycle (recommended: also cuts power); or
- **(b)** the digital RX chain is restructured into a deeper pipeline at 480 MHz, with at most one or two gates between flops. That is still at the limit at the slow corner, and the elastic-buffer write side would need a redesign.

On the TX side the last bit-rate stage is the serializer shift register. It probably fits (flop → mux → flop), but a real STA must confirm it, or the analog TX takes 2 or 4 bits in parallel and does the last serialization itself.

Next step: install OpenSTA (or use the analog team's / foundry STA flow) and repeat this with SDC multicycle constraints (WORK_PLAN 9.1).
