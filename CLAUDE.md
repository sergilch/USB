# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The digital ULPI side of a USB 2.0 PHY (HS / FS / LS), written in Verilog-2005. Every RTL file is `usb_*.v`, every testbench is `tb_<module>.v`, and all of them sit flat in the repo root. `./run_tests.sh` and `./run_synth.sh` run everything (the `Makefile` only wraps them, and `make` is not installed on this machine); outputs go to the git-ignored `build/`.

## Simulation (Icarus Verilog)

`./run_tests.sh` runs all testbenches in parallel, or only those whose name contains one of its arguments (`./run_tests.sh ulpi_core rx_`). It takes each build command from the testbench header, writes simulations, logs and VCDs to `build/`, skips TBs that need `X-FAB/` when it is missing, and exits non-zero on any failure. So the header command is the single source of the file list: keep it correct when adding files, and give every new testbench one (an `//   iverilog ...` line with `\` continuations).

Each testbench's header comment has the exact `iverilog` command and file list it needs. Read that header and use it rather than guessing at dependencies. Pattern:

```sh
iverilog -g2005 -o sim_bs usb_bit_stuffer.v tb_usb_bit_stuffer.v
vvp sim_bs
```

- Each testbench self-checks. It prints `TEST PASSED`, or `TEST FAILED: <n> error(s)`, or `TEST FAILED: timeout` from a watchdog. Check this line, not the exit code.
- Each testbench writes `tb_<module>.vcd` for waveform viewing.
- Unit testbenches: `tb_usb_bit_stuffer`, `tb_usb_tx_serializer`, `tb_usb_tx_sync_mux`, `tb_usb_nrzi_encoder`, `tb_usb_tx_path` (needs stuffer, NRZI and serializer), `tb_usb_tx_holding` (also needs `usb_ulpi_input_capture.v`), `tb_usb_ulpi_input_capture`, `tb_usb_ulpi_bus_owner`, `tb_usb_ulpi_reg_file`.
- RX unit testbenches: `tb_usb_rx_nrzi_decoder`, `tb_usb_rx_sync_detect`, `tb_usb_rx_bit_unstuffer`, `tb_usb_rx_deserializer`, `tb_usb_rx_eop_check`, `tb_usb_rx_elastic_buffer`, `tb_usb_rx_fsls_frontend`, `tb_usb_rx_hs_frontend` (each needs only its own module), `tb_usb_rx_status_sync` (also needs `usb_rx_status_flt.v`), `tb_usb_line_state`, `tb_usb_mode_term_ctrl`, `tb_usb_afe_trim_regs`.
- Integration testbenches: `tb_usb_ulpi_tx_top`, `tb_usb_ulpi_core`, `tb_usb_ulpi_phy_if` and `tb_usb_ulpi_phy_pads` (register access through the pads; build it with `-DDISPLAY_PD_PU_EN` so the pad pulls are modelled), from smallest to largest, and `tb_usb_rx_datapath` (TX→RX loopback: a far-end `usb_tx_path` on a ppm-offset clock, an HS CDR/squelch and FS/LS D+/D− line model, a raw symbol generator for protocol errors, and `usb_ulpi_rx_handler` behind the DUT), and `tb_usb_afe_tx_if` (`usb_tx_path` → `usb_afe_tx_if` → `afe_hs_tx_bm` / `afe_fsls_bm` → line: a cycle-exact pin model, line levels and HS / FS / LS reference decoders on the line), and `tb_usb_afe_rx_if` (line → `afe_hs_rx_bm` / `afe_squelch_bm` → ideal CDR or `afe_cdr_bm` → 6 × `usb_afe_rx_if` + `usb_rx_datapath` with different `HS_ZMIN` / `lock_dly` / `sq_comp`: pin model, lock-time margin, squelch sweeps; about 1 minute, set `NPKT` for statistics), and `tb_usb_pll_lock_det` (`afe_pll_bm` → `usb_pll_lock_det` + `usb_clk_gen`: lock / loss-of-lock timing, REFSEL, dead clock, CLKOUT pulse shape and stop / start), and `tb_usb_pwr_seq` (`afe_pll_bm` → `usb_pll_lock_det` + `usb_clk_gen` + `usb_pwr_seq`, with `usb_afe_tx_if` / `usb_afe_rx_if` / `usb_mode_term_ctrl` / `usb_rx_status_sync` behind an isolation-cell model and AFE inputs X while VDD33 is off: power-up order and times, low power with and without CLKOUT, loss of lock and relock, supply loss while transmitting and in low power, dead PLL with lock timeout and retry; no boundary signal X), and `tb_usb_afe_fsls` (FS / LS loopback, phase A5: device `usb_tx_path` → `usb_afe_tx_if` → `afe_fsls_bm` ↔ line ↔ host on a ppm-offset clock; device receivers → `usb_rx_status_sync` → `usb_line_state` + `usb_rx_datapath`; packets both ways, own-packet hold-off, and LineState against a classifier on the line voltages, glitch-free and within the latency limits; about 30 s), and `tb_usb_afe_chirp` (two PHY ends, device and host on a 400 ppm offset clock, each mode / termination control → `afe_term_bm`, `usb_tx_path` → `usb_afe_tx_if` → HS / FS drivers, and HS RX + CDR + FS receivers → `usb_rx_status_sync` / `usb_line_state` / `usb_rx_datapath`, with ULPI Link models on top: attach, reset, chirp K / host KJ chirps, switch to HS, HS packets both ways, disconnect, suspend, remote wake-up, resume with EOP; USB timers scaled down; about 10 s). Their file lists are long. Copy them from the header.
- AMS shadow testbenches: `tb_ams_link_shadow` (two `ams_phy_end` ends + `afe_*_bm.v` line, sequence `AFE/ams/ams_link_seq.vh`: attach, FS packets, chirp handshake, HS packets) and `tb_ams_pwr_shadow` (`usb_pwr_seq` + lock detector + CLKOUT + `afe_pll_bm`, LDOs as delays, `AFE/ams/ams_pwr_seq.vh`); the Spectre AMS tops with the same sequences are `AFE/ams/tb_ams_link.vams` / `tb_ams_pwr.vams`.

## Synthesis (Yosys)

`./run_synth.sh` (`CORNER=typ|slow|fast`) is a smoke test per top level (`usb_ulpi_phy_top`, `usb_ulpi_phy_pads`, `usb_rx_datapath`, `usb_ulpi_tx_top`, `usb_afe_tx_if`, `usb_afe_rx_if`, `usb_clk_gen`, `usb_pll_lock_det`, `usb_rx_status_sync`, `usb_line_state`, `usb_mode_term_ctrl`, `usb_pwr_seq`, `usb_afe_trim_regs`). It runs `synth -flatten`, fails on any latch and on `check -assert` problems, then maps to the X-FAB D_CELLS_JIHD library (`X-FAB/xh018_lib`), requires that no generic cells are left, and reports cells, flip-flops and area. BBSUD8F is a black box whose ports are cut out of `X-FAB/BBSUD8F.v` at run time (Yosys can't parse the vendor model: XL directives, polarity `specify` paths). Without `X-FAB/` only the generic part runs and the pad wrapper is skipped. No timing analysis yet. Keep new RTL synthesizable and latch-free; add a new top level to `TOPS` in the script.

**Status:** all 38 testbenches (32 RTL, 4 AFE-model, 2 AMS shadows) build and pass with Icarus Verilog (installed on this machine). The AFE boundary blocks `usb_afe_tx_if` (AFE plan A2), `usb_afe_rx_if` (A3) and the clock blocks `usb_clk_gen` / `usb_pll_lock_det` (A4) were added on 2026-11-10 and are not wired into the top level yet (`ce60` / `clk60` are still inputs of `usb_ulpi_phy_pads`). ## Architecture

Hierarchy, top down:

```
usb_ulpi_phy_pads           BBSUD8F pads (CLK, DATA[7:0], DIR, NXT, STP, RESETB), ULPI protection
│                           pulls (Interface Control bit 7), RESETB synchronizer, NAND tree
└── usb_ulpi_phy_top
usb_ulpi_phy_top            phy_if + register file; maps comparators -> VbusState,
│                           XcvrSelect -> TX speed
├── usb_mode_term_ctrl      pull-up / 45 Ohm / pull-down enables (Table 5-1, break before make),
│                           OpMode 10 -> bypass + no SYNC + no EOP (host FS/LS: EOP), 01 -> drv_dis
├── usb_ulpi_reg_file       the only register file: immediate set, mirrored at ext 00h-3Fh; IE masks;
│                           vendor 30h-3Fh passed to usb_afe_trim_regs
├── usb_afe_trim_regs       AFE trims (shadow + UPDATE -> active), TEST (ATB, loopback), PWR_STAT, lol_clr
└── usb_ulpi_phy_if
    ├── usb_ulpi_core
    │   ├── usb_ulpi_input_capture   registers pins, decodes TXCMD / RegWrite / RegRead / ext (AFh/EFh)
    │   ├── usb_tx_datapath          holding -> SYNC/PID mux -> usb_tx_path (bit stuffer -> NRZI -> serializer+EOP)
    │   │   └── usb_tx_holding       4-byte FIFO, paces the Link with NXT, ends packet on STP
    │   ├── usb_ulpi_reg_access      register read/write FSM toward reg_*
    │   ├── usb_ulpi_burst_mux       merges register read data with PHY bursts (arb_*)
    │   └── usb_ulpi_bus_owner       drives DIR / NXT / DATA out + OE, handles turnaround
    └── usb_ulpi_rx_path
        ├── usb_ulpi_rx_handler      RX data FIFO (RX_DEPTH), RxActive/RxError, overrun
        ├── usb_ulpi_rxcmd_gen       RXCMD bytes from linestate/VBUS/ID/interrupt changes
        └── usb_ulpi_out_arbiter     RX data vs RXCMD -> ext_* burst into the core
```

RX datapath (standalone for now, drives the `rx_*` inputs of `usb_ulpi_rx_path`):

```
usb_rx_datapath             mode select (XcvrSelect), local-TX hold-off, output stage (one event per ce60 tick)
├── usb_rx_hs_frontend      HS: captures CDR data on clk_rx, syncs squelch / CDR lock / enable
├── usb_rx_decoder (HS=1)   on clk_rx
├── usb_rx_elastic_buffer   ASYNC=1, clk_rx -> clk_bit, 16 events
├── usb_rx_fsls_frontend    FS/LS: syncs D+/D-/rxrcv, DPLL (40x / 320x oversampling on clk_bit)
├── usb_rx_decoder (HS=0)   on clk_bit
└── usb_rx_elastic_buffer   ASYNC=0, 4 events
usb_rx_decoder: usb_rx_nrzi_decoder -> usb_rx_sync_detect -> usb_rx_bit_unstuffer
                -> usb_rx_deserializer -> usb_rx_eop_check (START / BYTE / END(err) event words)
```

`usb_afe_tx_if` (standalone for now, sits behind `usb_tx_path`): retiming flops toward the AFE pins (`hs_tx_p/n`, `hs_tx_en`, `fs_oe/dat/se0/ls`), HS/FS/LS driver select, `TX_EN` lead / lag via a one-hot-entry delay line, idle clamp (`drv_dis`, `iso_en`), `lead_first` (OpMode 10: the lead shows the first bit, not J, so a chirp K has no J in front). Data latency `tx_lead` + 3, `TX_EN` 3. Pin names and timing follow `DOC/afe_interface_spec.md` 3.1 / 3.4 / 4.1.

`usb_afe_rx_if` (standalone, in front of `usb_rx_datapath`'s HS inputs): `RX_EN` / `CDR_EN` (on in HS mode only), input isolation, squelch synchronizer on `clk_rx`, `hs_cdr_lock` = `lock_dly` bits after squelch release, data delayed by 3 + `sq_comp` against squelch / lock 3. Recommended: `lock_dly` 2 with `HS_ZMIN` 4, `sq_comp` 0 (spec 4.2).

`usb_clk_gen`: `ce60` (registered, ÷8) and `clk60` / CLKOUT from a falling-edge flop (rises half a cycle before the `ce60` edge, 4 + 4 cycles), enable taken once per period so CLKOUT stops low; `clk_on` = 0 is the safe point to stop the PLL. `usb_pll_lock_det`: counts `clk_bit` over 256 `ref_clk` cycles (5120 ± 5 at 24 MHz), 4 good windows → `pll_lock`, one bad → unlock + sticky `lol`; timeout for a missing reference, a `ref_clk`-side heartbeat check for a dead `clk_bit`, REFSEL → `fb_div` / `refsel_err`. Both use the power-on reset, not RESETB.

`usb_pwr_seq` (standalone, runs on `ref_clk` = REF_DIG because `clk_bit` is off before lock and in low power; reset `por_n`): OFF → BIAS (`BIAS_CYC`) → PLL (lock timeout `LOCK_TO` → sticky `pll_err`, `OFF_CYC` off, retry) → release (`iso_en` 0, core reset off, `clk_en`) → RUN once CLKOUT runs (`dir_hold` 0, `afe_en` 1). Low power: `susp_req` drops `afe_en`; with `clk_susp` CLKOUT stops low (`clk_on` = 0) before `pll_en` falls; wake relocks and restarts CLKOUT before DIR is released. Loss of lock in RUN goes the same way (relock, the core keeps its state). Supply loss (`pwr_good` / `pg18a`) → OFF at once; `pll_en` waits for CLKOUT to stop unless VDD18A is going. `ldo_en` = `por_n`. clk_bit-side copies: reset, isolation and DIR hold assert asynchronously (no clock needed) and release after 2 `clk_bit` edges. `usb_afe_trim_regs`: map in its header (30h–36h trims, 3Ch TEST, 3Dh PWR_STAT, 3Eh TRIM_CTRL UPDATE / RDACT), one address per register (no set / clear aliases), combinational read.

`usb_mode_term_ctrl`: termination enables per USB3320 Table 5-1 (host = DpPulldown and DmPulldown; 45 Ω = XcvrSelect 00 + TermSelect 0; DP pull-up = peripheral, TermSelect 1, XcvrSelect ≠ 10; DM pull-up for LS; OpMode 01 all off), registered on `ce60`, break before make (`BBM_TK` ticks after any "off" before an "on"), all off in reset / `iso_en`. TX framing and `drv_dis` are combinational from the registers. The HS handshake itself is run by the Link (decision D3); the PHY only provides chirp TX (OpMode 10), chirp LineState and the terminations.

`usb_rx_status_sync` (standalone, the single synchronization point for the analog status outputs): 2-FF only for `rxdp` / `rxdm` / `rxrcv` (the DPLL and LineState need every edge), 2-FF + inertial filter (`usb_rx_status_flt`, `sq_flt` / `disc_flt` clk_bit cycles) for squelch / disconnect, 2-FF + debounce in `ce60` ticks (`vb_flt`) for VBUS / ID, so those change on `ce60` only. Resets to the isolated values. `usb_line_state`: LineState sampled per `ce60` tick, FS / LS `{DM, DP}` with SE0 / SE1 shown only after 2 (FS) / 14 (LS) ticks (skew filter, UTMI+), HS `squelch ? 00 : 01`, chirp (OpMode 10) `squelch ? 00 : rxrcv ? J : K` with a 2-tick filter; HostDisconnect in HS host mode (`host_mode`, OpMode 00) from `disc` ORed over the TX window (`hs_tx_act` + `DISC_TAIL`), updated once per packet. Outputs change on `ce60` only.

`usb_ulpi_tx_top` is an older, smaller top level: capture + TX datapath + bus owner, with no register access. Its register and RX hooks are left as open ports. `tb_usb_ulpi_tx_top` still tests it.

### Rules that hold across all files

- **One clock** (one exception, below). Everything runs on `clk_bit` (480 MHz). The 60 MHz ULPI domain is the clock enable `ce60`: high for one `clk_bit` cycle in eight, aligned with clk60. Logic in the ULPI domain must update only on `ce60` (some submodules call the port `ce`). Signals in that domain are 8-cycle multicycle paths. Active-low async reset is `rst_n`.
- **The exception: `clk_rx`**, the clock recovered by the HS CDR (assumption D1 in WORK_PLAN.md). Only `usb_rx_hs_frontend`, the HS `usb_rx_decoder` and the write side of the HS `usb_rx_elastic_buffer` run on it; the elastic buffer (Gray pointers) is the only crossing. `usb_rx_datapath` synchronizes the reset release for it. FS/LS receive is recovered digitally on `clk_bit` (assumption D2).
- **Speed encoding** is ULPI XcvrSelect everywhere: `00` HS, `01` FS, `10` LS, `11` sent at FS rate (LS-via-FS-preamble is not implemented). Speed is sampled at packet start. FS/LS bit rates come from the `FS_DIV=40` / `LS_DIV=320` dividers on `clk_bit`, and `DIV_W` sets the counter width.
- **Line encoding:** `txd` J = 1 / K = 0, LSB first. HS EOP is 8 bit times at the inverted level. FS/LS EOP is SE0 for 2 bits (`tx_se0`), then J for 1. In HS the serializer needs a word every `ce60`. If one is missing, the packet ends with an EOP and `tx_underrun` pulses. With `eop_dis` (OpMode 10 except a host at FS / LS, decision D4) there is no EOP: `tx_en` drops after the last bit.
- **Keeping TX and register transfers apart** (see `usb_ulpi_core.v` header): a register command is not acknowledged while `usb_tx_holding` is busy. TXCMD decode is inhibited while `reg_link_busy` is set, because payload, address and data bytes can look like commands. The bus owner never takes the bus while either transfer is active. Between the acknowledge of a register read and its data (`rd_pend` from reg_access), `usb_ulpi_burst_mux` starts no PHY burst, so the read data is the first byte after the turnaround and never trails an RXCMD. Keep these interlocks when changing capture, holding, reg_access or bus_owner.
- **Register read timing is fixed** (ULPI 1.1 Fig. 22 / 30): if NXT consumes the last byte of the read in tick N, the turnaround is in N+1, the data in N+2 and DIR falls in N+3. `rd_turn` from reg_access makes the bus owner take the bus although NXT is high, and the read happens in the turnaround tick, using the captured command or address byte. So the register file must answer in the same tick (`reg_rdata` combinational, `rd_valid = reg_rd`); a register that can't do that can't sit behind this interface.
- **ULPI holding state** (§3.12, in `usb_ulpi_core`): STP high while the Link owns the bus and neither TX holding nor reg_access is busy means "Link not driving". No command is decoded (`cmd_ok`), DIR stays low (`holding` into the bus owner's busy input), and pending RXCMD changes go out as one RXCMD afterwards. An STP that ends a transfer is expected and does not count.
- **Bit stuffing:** the counter restarts at each packet, and SYNC goes through as ordinary data. A stuff bit is still inserted when six 1s end the packet. On RX the unstuffer loads its run counter with 1 on the final 1 of SYNC, to match.
- **RX framing:** HS EOP = bit-stuff violation with exactly 7 residual bits; FS/LS EOP = SE0 bit with 0 residual bits; anything else ends the packet with `rx_error`. SYNC detection needs `HS_ZMIN=6` / `FS_ZMIN=4` zeros before the final 1, and after a packet it only rearms on SE0 or when the HS receiver goes inactive (squelch), so data that looks like SYNC never starts a packet.
- **Not implemented yet** (exported only, no logic reacts to them): OpMode `11` (transmits like `00`), `soft_reset`, SuspendM / low-power (`dir_hold` is an input from the future low-power controller; `usb_pwr_seq` takes `susp_req` / `clk_susp` / `wake` from it). The VBUS / ID comparators and the AFE are also outside this repo; low-power LineState (combinational on DATA[1:0]) and resume / reset wake-up events are not in `usb_line_state` yet.

### Testbench style

The integration testbenches model a ULPI Link at the pins. The model holds each byte until NXT, retries a command when it loses to DIR, and flags protocol errors. It takes register read data from the pins only and checks the fixed read timing. They check register contents against a shadow model and rebuild every TX packet from `txd`/`tx_en`/`tx_se0` (de-NRZI, de-stuff, EOP timing). Register data deliberately uses bytes that look like commands (40h, 4Fh, 80h, AFh, C0h, EFh, 2Fh). New testbenches should follow the same pattern: an `errors` counter, the `TEST PASSED`/`TEST FAILED` line, a timeout watchdog and a VCD dump.

Each module's header comment holds its detailed spec (pipeline position, timing, corner cases). Read it before you edit the module, and keep it up to date.
